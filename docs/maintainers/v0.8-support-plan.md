current integration implements the M1 feature slice; it remains unmerged while
MCP Description v0.8 is finalized and additional V2 work proceeds.

> `0.8.0-rc.1` and the instance `$schema` URI

## What v0.8.0-rc.1 changes

Breaking vs 0.7 (document shape genuinely differs):

- `info.protocolVersion` removed → required **root `protocolVersions`** (closed set of MCP revisions).
- `capabilities` object → **array of protocol-scoped Capabilities Objects**.
- Inline security → named root **`securitySchemes`** + Security Requirement Arrays.
- Every Tool requires an object-rooted **`inputSchema`**.
- `transports` now optional; ordinary collections must be non-empty when present.

New capabilities:

- MCP **`2026-07-28`** protocol support (stateless protocol) and multi-revision servers.
- Protocol applicability/scoping on transports, capabilities, tools, resources, resource templates, prompts.
- Deterministic **Effective Protocol Views** (projection) + conflict-detecting merge.
- Root `instructions`; formal `capabilities.extensions`.
- **Examples**: tool `examples`, tool `interactionExamples`, resource examples, prompt examples, completion examples.
- Reusable **`components`** + local **`$componentRef`** Reference Objects.
- Operation-level **elicitation declarations**.
- Object-level **`x-*`** specification extensions; **`_meta`** support.
- Primitive **`clientRequirements`**.
- JSON and restricted YAML as equally conforming serializations.

## Ecosystem packages

  `parseMcpDescriptionSource`, `serializeMcpDescription` (JSON/YAML),
  `projectEffectiveProtocolView`, `selectMcpDescriptionDeclarations`,
  `migrateMcpDescription07ToRc1`, deterministic migration reports, and `RC_1_*`
  snapshot constants. Draft 4 operations remain available but are not the editor target.
  Subpath exports: `@mcpdesc/core/documents` (parse/serialize, validator-free)
  and `@mcpdesc/core/selection`. Internally imports
  **`@mcpdesc/validator/standalone`** (CSP-safe). Local:
  `/home/daggit/repos/github.com/mcpdesc/core`.
- **`@mcpdesc/validator` v0.7.1** — `validateMcpDescription(doc, { specification })`
  for selectors `0.8.0-draft.1..4` **and `0.8.0-rc.1`**. Two entries:
  the default (`.`) is AJV-runtime (fast, **not** CSP-safe) and
  **`@mcpdesc/validator/browser`** and `/standalone` are CSP-safe entries (precompiled fixed
  schemas + an interpreted evaluator for document-provided Tool/Elicitation

  Also exports `resolveMcpDescriptionSpecification` for `$schema`-based
  selector resolution.

## CSP spike results

### Round 1 (2026-08-31) — `core@0.2.0` + `validator@0.4.0`: BLOCKED

Under a simulated strict CSP (`new Function`/`eval` disabled, matching
`script-src 'self'`): the bundle contained AJV's runtime `new Function`, the
**module import itself threw** (eager AJV compile at init), and even importing
only parse/serialize from core's barrel threw because it transitively pulled the
validator. Neither package was usable under the CSP.

### Round 2 (2026-09-01) — CSP packaging blockers: RESOLVED

Both upstream asks landed. Re-ran the CSP simulation (trap `new Function`/`eval`
**before** import; count codegen attempts) against each entry:

| Entry | Import | Call | Result | Codegen attempts |
|-------|--------|------|--------|------------------|
| `@mcpdesc/validator` (default) | **throws** | — | not CSP-safe (expected) | 1 |
| `@mcpdesc/validator/standalone` + `validate` | ok | ok | `valid:true` | **0** |
| `@mcpdesc/core` (barrel) + `projectEffectiveProtocolView` | ok | ok | `ok:true` | **0** |
| `@mcpdesc/core/documents` + parse/serialize | ok | ok | `parsedOk:true` | **0** |

Robustness (standalone, under CSP): a deliberately invalid doc correctly returns
`valid:false` with a `schema-validation` diagnostic (not silently passing), and a
doc with tool `examples` (heaviest interpreted embedded-schema path) validates
`valid:true` — both with **0** codegen attempts.

**Conclusion:** the editor can adopt `@mcpdesc/validator/standalone` and
`@mcpdesc/core` directly under the existing strict CSP, with full structural +
semantic validation. The interim self-precompiled validator is no longer needed.
The editor **must import the `/standalone` validator entry** (never the default)
and keep it out of any bundle path that would pull the AJV runtime entry. RC.1
operations require `@mcpdesc/core@0.4.0`; the earlier CSP spike established the
packaging behavior that 0.4.0 retains.

### RC.1 verification (2026-09-01) — `core@0.4.0` + `validator@0.5.0`: PASSED

A fresh published-package check exercised `RC_1_SPECIFICATION`,
`RC_1_SCHEMA_URI`, RC.1 standalone validation, Effective Protocol View
projection, and the `migrateMcpDescription07ToRc1` export with `new Function`
and `eval` blocked before import. Validation returned `valid:true` with zero
diagnostics, projection returned `ok:true`, the migration export was present,
and the test recorded **zero code-generation attempts**.

## Workstreams

### A. Validation & CSP (implemented)
1. Adopt **`@mcpdesc/validator/standalone`** for structural + semantic validation
   under the existing strict CSP (verified codegen-free). No interim
   self-precompiled validator needed. Map its diagnostics onto the editor's
   `ValidationResult` shape; keep the AJV **default** entry out of the bundle.
2. Keep Monaco's JSON-schema association pointed at the vendored 0.8 schema for
   editor autocomplete/squiggles (separate from the semantic validator).
3. Use `resolveMcpDescriptionSpecification` / instance `$schema` for selector
  resolution. Require `0.8.0-rc.1` and its exact schema URI; the `mcpdesc` field
  stays `0.8.0` and never selects a snapshot.

### B. Core integration (implemented)
- Add `@mcpdesc/core@^0.4` + `@mcpdesc/validator@^0.5` deps. CSP bundle safety is
  **verified** (see spike round 2) — import `@mcpdesc/validator/standalone` and the
  `@mcpdesc/core` barrel; add a lint/build guard so the AJV default entry never
  enters the bundle.
- Replace ad-hoc JSON/YAML parsing in `useDoc` with core parse/serialize
  (`@mcpdesc/core/documents`).
- Wire `projectEffectiveProtocolView` + `selectMcpDescriptionDeclarations`.

### C. Data model & types (implemented for M1; typed placeholders retained for later features)
- Rewrite `src/core/types.ts` for 0.8 (protocolVersions, capabilities array,
  securitySchemes, mandatory object inputSchema, optional transports) with typed
  placeholders for examples, components, elicitation, clientRequirements, `_meta`,
  `x-*`.

### D. State (`useDoc`) rework (implemented)
- Model protocol-version awareness and the selected effective view; update the
  debounced parse+validate; add migration state for imports.

### E. Editor (Monaco) (implemented)
- Associate Monaco JSON schema with the vendored 0.8 schema; refresh bundled
  examples for the new required shape.

### F. Preview / CardView / viewer package (M1 implemented)
- Update `McpDescCardView` (shared with `packages/mcptoolkit-viewer`) for the
  capabilities array, protocolVersions, securitySchemes, and an EPV toggle.
  Update `template.ts`/`renderer.ts`. Version the viewer independently.

### G. Migration UX (implemented)
- Detect `mcpdesc: 0.7.0` after parsing and request confirmation before invoking
  `migrateMcpDescription07ToRc1`, preserving the source JSON or YAML serialization.
- Make **Migrate** the default Enter action; Cancel preserves the original source
  and suppresses repeated prompts until the document changes.
- Use the converter's explicit `2025-11-25` protocol default when the legacy
  document omits `info.protocolVersion`; surface the resulting warning.
- Keep cancelled and failed documents in an unsupported-version preview. Show a
  compact migration outcome at the bottom of the preview and allow deterministic
  JSON reports to be downloaded for successful and failed conversions.
- Documents before 0.7 remain unsupported.

### H. Repo / release plumbing (deferred until v0.8 ships)
- Bump root + editor-dist to `2.0.0-rc.x`; roll up the three changelogs; refresh
  README badge/spec-version references; update `docs/`.

## Milestones

- **M1** — CSP-safe structural validation + core parse/serialize + 0.8 types/state
  + Monaco schema + **protocol scoping / Effective Protocol View** + **securitySchemes**
  in editor & card view + 0.7 import. **Implemented on `v2/main`; held for the
  v0.8 release window.**
- **M2** — named examples for tools, resources, resource templates, prompts,
  interactions, and completions are implemented as lightweight source links in
  the editor, with configurable standalone rendering. Reusable `components` /
  `$componentRef` UI remains.
- **M3** — elicitation declarations, `clientRequirements`, `_meta`, `x-*`; full
  semantic diagnostics surfaced in the validation panel (already available via
  `@mcpdesc/validator/standalone`).
